## What this says about model choice

- Codex `gpt-5.6-sol` at the CLI default effort is the workhorse: code-feature 85% first-try
  (n=26, 50k tokens median), code-fix 86% (n=14, 52k).
- `gpt-6-astra` is 8/8 first-try across code-feature and code-fix at the same ~49k tokens: the
  strong lane is not the expensive lane in this log.
- Codex `medium` effort: code-fix 5/5 at 32k tokens, docs 4/4, code-feature 8/13 (62%).
- Codex `high` effort looks bad (code-feature 2/5, 118k tokens) but the sample is the broken-check
  runs; code-review at high is 8/8. Thin and confounded.
- Claude sonnet's failures are engine-shape failures, not model failures. Until the claude engine
  can run Bash or write outside its dir, route it only tasks whose check inspects files in the task
  dir and needs no test run.
- Gemini flash: format-conversion 4/5 at 25k tokens and 12 s. Nothing else proven.

## Fixes that need no model change (in priority order)

1. Run every check against the clean tree before any worker spawns, and abort on broken-check
   markers (`usage:`, `syntax error`, `command not found`, `Traceback`, `FATAL`, `panic`, timeout).
   Would have saved ~2.5M tokens in this log.
2. Keep checks under the 60 s cap: no `npm run build` inside a check; build in the worker, verify
   the artifact in the check (6 attempts, 565k tokens hit the cap).
3. Lint advisory on specs over 6k chars.
4. Stale worktree taskdirs: remove and continue instead of failing setup.
5. Count claude tokens properly (sum input, cache creation, cache read, output) so the scoreboard
   compares like with like.
